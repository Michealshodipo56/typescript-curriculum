## Inspection method

Every imported file was read by a full-byte traversal and matched to its pinned SHA-256 inventory. Each path has an individual role and inspection evidence in [file-review.json](curriculum/file-review.json). Exercise ordering was evaluated from canonical prompts, TODOs, templates, tests, and available solutions; it was not generated by sorting filenames, titles, or upstream difficulty labels.

Supporting files were reviewed structurally for their role: metadata and dependency lockfiles parsed, code declarations and task/error markers extracted, generated indexes distinguished from exercise directories, SVG files parsed, and raster headers/dimensions verified. Localized READMEs and metadata were associated with their canonical question; this is not a line-by-line translation-quality review. Neither a dependency security audit nor an execution certification of the three upstream applications is claimed.

## Findings affecting placement or completion

1. TypeScript Exercises folder 16 is a congratulations page; `test.ts` explicitly has nothing to test. It must not become a learner task.
2. TypeScript Exercises exercise 13 calls its augmentation a `.d.ts` file in the prose, while the actual editable disk path is `module-augmentations/date-wizard/index.ts`. The UI maps that file into a virtual `.d.ts` path. The sequence records the real editable path.
3. TypeScript Exercises runs isolated virtual projects via `src/lib/exercise-structures.ts` and its compiler worker. A root application build is not a replacement for checking each exercise, and bundled exercise libraries are essential fixtures rather than disposable dependencies.
4. Source compiler generations differ: TypeScript Exercises declares `~3.7.2`, Type Challenges declares `^5.3.3`, and birsi declares `^5.6.0`. The sequence is conceptual and preserves source environments; consolidating runtimes is separate work. Avoid assuming a newer compiler preserves every historical diagnostic.
5. Deep Readonly and DeepMutable prose understates the included tuple/function cases. The preserved test contract controls the assigned work.
6. Chainable Options prose says keys do not repeat, but the tests require duplicate-key errors. Both the diagnostic and downstream type expectations matter.
7. Unbox presents recursive and bounded recursion as bonuses, but the test file exercises them. Its zero depth means unlimited unboxing in this snapshot.
8. Unique Items includes element-specific error diagnostics in its supplied tests even though the prose labels them bonus. Those directives must not be erased to obtain a pass.
9. Trunc returns strings in tests. ObjectEntries retains undefined for optional fields in this snapshot. Join tests an omitted separator. Slice tests omitted bounds. String-to-Number rejects trailing invalid text rather than accepting the numeric prefix like JavaScript parseInt.
10. Assert Array Index needs the question metadata override `noUncheckedIndexedAccess: true`; that override is not present in the shared base configuration. Its brands describe an API discipline, not runtime bounds validation.
11. Construct Tuple and Subtract contain deliberate compiler-depth expected-error cases. Long-string tasks are progressive scaling exercises. Historical prose about a single fixed recursion-depth limit is not treated as a universal compiler guarantee.
12. Get Readonly Keys is marked extreme upstream, yet it fits after modifier-sensitive equality and Mutable Keys. Conversely several medium combinatorial/parser tasks need more foundations than an initial easy/medium split suggests.
13. The six short files under Type Challenges `guides/` contain TODO placeholders. They cannot serve as complete teaching prerequisites. The guided birsi material and explicit reading bridges cover the relevant introductions.
14. TypeScript Training assertions mainly verify static contracts, not runtime correctness. Its index-signature lesson comments imply unchecked access is enabled, but its shared configuration does not enable `noUncheckedIndexedAccess`. Keep the requested explicit return type and independently check missing-key behavior.
15. Existing solutions are references, not authoritative replacements for task rules. Some use inference, casts, or any where a learner-facing task asks for more discipline; the curriculum retains the source-specific rules and does not publish new solution code.
16. JSON Schema extras are not exhaustively tested by the included base test cases. Sort and Maximum likewise name extensions beyond their core assertions. They remain explicit extension work rather than claims of existing grader coverage.
17. E14 contains conflicting property-getter argument orders: the supplied runtime implementation is object-first, while the tests and callable interface expect key-first. The source warns that its JSDoc can be inaccurate. Follow the tested API when doing the task and check runtime behavior; this review preserves the source rather than silently repairing it. E15 reference typing intersects added fields with the previous object, while runtime spread overwrites them; conflicting existing-key updates are not covered by its supplied tests.
18. Vue Basic Props explicitly follows Simple Vue. Decimal Multiply explicitly follows Sum. The three String Length tasks progressively raise scaling requirements. These order constraints are recorded and checked.

## Coverage and validation

- Every permitted imported file has exactly one ledger entry, including dotfiles, tracked exercise-local node_modules fixtures, metadata, translations, licenses, and assets.
- Every birsi lesson and every one of its 52 Task markers is represented.
- Every actionable TypeScript Exercises folder 1–15 occurs once. Folder 16 is accounted for as supporting completion material.
- Every one of the 190 Type Challenges question directories occurs once, independent of whether a generated source README index lists it.
- Relative instruction, editable, and test paths exist. Module numbers and global order numbers are consecutive; unit IDs are unique.
- Explicit dependency edges point forward in the chosen order. Source-related links are not automatically treated as directed prerequisites.
- Original imported file content and Git file modes remain unchanged. The collection's existing checksum verifier is retained and used.

The validation checks document coverage and preservation. They do not solve or execute the 217 learner exercises.
